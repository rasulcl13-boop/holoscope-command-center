# PZ65 Studio — локальная адаптация P56 Studio

Основа: [trackerr/p56-studio](https://github.com/trackerr/p56-studio), MIT, commit `dcc7d181b0766943f2df3efecd3f9c43d13c1706` (последний доступный при проверке 30 октября 2026). Оригинальные исходники, README и LICENSE сохранены. Это локальная адаптация, не официальный релиз автора P56 Studio.

## Запуск

Двойной клик по `../Запустить PZ65 Studio.command`, затем открыть http://127.0.0.1:8765/ . Или:

```sh
/usr/local/bin/python3 launch.py
```

Готовый бинарник `bin/pz65-server` собран для Apple Silicon. Запуск читает состояние устройств и не включает питание автоматически. Для загрузки выбрать основной контроллер **06272470**, включить установку и перейти в **MEDIA**. На связи должны быть все три известных устройства.

`python3 launch.py --preview` запускает отдельный виртуальный P56 на 8766; реальное оборудование в этом режиме не обнаруживается. `--background` оставляет процесс работать после завершения команды. PID, адрес и путь журнала записываются в `run.json`.

## Изменения относительно готового решения

- Отдельный профиль **PZ65/type26**: обычный JPEG 512×512, вписанный на чёрный фон, без полярного преобразования P56. Поворот и масштаб предварительного просмотра относятся к подготовке материала.
- Одиночное изображение отправляется как 100 одинаковых кадров / 5 секунд. Команда завершения — один **COMMIT=0**, без OFF/ON. Требуется ACK имени и новый плейлист, содержащий файл. Используется свободное числовое имя до 8 цифр, произвольное исходное имя заменяется автоматически.
- После сохранения выбирается фактический слот нового файла, затем PLAY и повтор текущего файла. Подтверждение по телеметрии требует удержания 6 секунд.
- Загрузка разрешена через основное устройство 06272470 при наличии трёх известных PZ65; чужие имена отклоняются. Поиск и идентификация не привязаны к DHCP-адресам.
- Перезапись существующих файлов в профиле PZ65 отключена. Live cast и временные уведомления `/api/show` для PZ65 возвращают явную ошибку: работа этих режимов не подтверждена.
- События соединений, статусы, плейлисты, ошибки и команды пишутся в `logs/*.jsonl`; текстовый журнал — соседний `.log`. Время JSONL — Unix milliseconds, текстовый журнал — UTC.

## Что проверено и что осталось

27 unit-проверок ядра, 17 проверок сервисного слоя и отдельный сквозной тест с тремя виртуальными PZ65 прошли. Сквозной тест проверяет 100 кадров, 512×512, выбор нового слота, два однократных COMMIT на две передачи, отказ при дубликате/неверном контроллере, отсутствие OFF/ON/форматирования/сброса/удаления и сохранение угла/яркости.

После перехода на новый сервер все три **реальных** PZ65 подключились, их имена, плейлисты, углы, яркость и выключенное питание совпали с сохранённым состоянием Python-контроллера. Новая загрузка через Rust-контроллер на реальном оборудовании ещё не выполнялась; аппаратное подтверждение формата относится к предыдущему Python-контроллеру. Видео до 60 секунд допускаются кодом; физически все такие длительности не проверены.

**Порядок старых фрагментов после перестановки карт пока не исправлен.** У готовой основы нет реализации сшивания; назначение групповых позиций и возможность перенести уже записанные фрагменты требуют отдельной проверки. Замена контроллера сама по себе не переставляет медиа между картами.

## API

Сохранён API P56 Studio: `GET /api/state`, `GET /api/events`, `POST /api/call/<command>`. Устройства имеют числовой `id`; постоянное имя нужно брать из `devices` ответа `/api/state`. Старые Python endpoints `/api/power`, `/api/upload` отличаются и не должны использоваться с новым сервером.

Подготовка/загрузка в интерфейсе работает через `load_media` / `upload`. На этапе адаптации предпочтителен интерфейс MEDIA. Автоматического удаления новых материалов нет.

## Сборка

Из корня исходного рабочего проекта:

```sh
RUSTUP_HOME="$PWD/work/rustup" CARGO_HOME="$PWD/work/cargo" \
  work/cargo/bin/cargo build --manifest-path outputs/pz65-studio/Cargo.toml --locked -p p56-server
cp outputs/pz65-studio/target/debug/p56-server outputs/pz65-studio/bin/pz65-server
```

Rust установлен только в рабочие `work/rustup` и `work/cargo`; системный PATH не изменялся.

## Возврат к прежнему контроллеру

Сначала остановить PID из `run.json` (Ctrl+C в терминале обычного запуска либо SIGTERM для фонового процесса), затем запустить `../holoscope_api.py`. Python-реализация и её материалы сохранены. Два контроллера одновременно не запускать на TCP6666.


## Командный центр — 31 октября

Рабочий интерфейс обновлён в стилистике научно-фантастического HUD: тёмно-синий фон, голубые контуры, радиальная схема установки и карточки трёх постоянных ID. По умолчанию выбирается основной контроллер 06272470.

Главный экран показывает реальные подключения, питание, яркость, число файлов, текущий слот и журнал. Диаграмма обозначена как условная схема; предпросмотр материала не выдаётся за изображение с камеры. Питание, пауза, яркость и повтор работают через прежний API P56 Studio. Точные настройки и обслуживание вынесены в раскрываемый блок. Загрузка, медиатека, сеть и системные настройки сохранены отдельными разделами.

Добавлена русская локализация основных панелей; английские и голландские переводы сохранены. Декоративное вращение отключается при системной настройке уменьшения движения.

Исходники оболочки: `app/ui/src/App.tsx`, `app/ui/src/panels/CommandCenter.tsx`, `app/ui/src/command.css`. Результат сборки по-прежнему один самодостаточный `app/src/index.html`, встроенный в `bin/pz65-server`. Для повторной сборки UI после установки зависимостей: `node node_modules/typescript/bin/tsc -b` и `node node_modules/vite/bin/vite.js build` из `app/ui`. Затем пересобрать Rust-сервер согласно разделу выше.

Проверены браузером размеры 375/768/1024/1440 CSS-пикселей, все шесть разделов, команды на изолированном симуляторе, отказ команды и потеря связи. Ошибок JavaScript в рабочем браузере нет. После обновления три реальных устройства подключены, статусы и файлы совпадают с состоянием перед перезапуском. Новые материалы на оборудование не отправлялись. Отчёт — `hud-verification.json`, снимок — `command-center.jpg`.

Ограничение Live cast и незавершённая проверка новой Rust-загрузки на аппаратуре остаются в силе. [Системное уменьшение движения — MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion).
